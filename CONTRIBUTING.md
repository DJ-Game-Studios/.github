# Contributing to DJ Game Studios projects

Thanks for taking the time to help.

Our public repositories have different maturity levels. Before opening a pull request, read the repository README and existing issues to confirm that the project currently accepts the kind of change you have in mind.

## Report a bug

Open an issue in the affected repository and include:

- the release version or commit;
- your operating system and relevant application version;
- clear steps to reproduce the behavior;
- what you expected and what happened instead;
- a minimal log or screenshot when useful.

Remove usernames, file paths, tokens, and other personal or secret information from attachments and logs.

## Suggest a feature

Describe the problem first, then the outcome you would like. Small, concrete proposals are easier to evaluate than broad redesigns. Please do not begin a large implementation until a maintainer confirms the direction.

## Submit a change

1. Keep the pull request focused on one problem.
2. Follow the repository’s existing style and test instructions.
3. Add or update tests for behavior changes.
4. Update public documentation when the user experience changes.
5. Explain what changed, why, and how you verified it.

By contributing, you agree that your work may be distributed under the license of the repository receiving it.
